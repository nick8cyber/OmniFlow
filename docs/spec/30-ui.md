### StampedMenuBarIcon (рисование в коде, не ассет)

`NSImage` размера `NSSize(width: 18, height: 16)`, `flipped: false`, `isTemplate = true`.

(xRadius 3, yRadius 3) минус 5 вертикальных «столбиков»-эквалайзера
(каждый — rounded rect, xRadius/yRadius 0.75, ширина 1.5):

| x | y | height |
|------|-----|--------|
| 3.0 | 7.0 | 2.0 |
| 5.5 | 5.0 | 6.0 |
| 8.0 | 3.0 | 10.0 |
| 10.5 | 4.0 | 8.0 |
| 13.0 | 6.0 | 4.0 |

Заливка `NSColor.black`. Т.е. иконка «волна в скруглённой плашке», template —
меню-бар сам красит в чёрный/белый.

## 2. AppDelegate: окна и activation policy

### 2.1 Свойства

- `let appState = AppState()`
- `var setupWindow: NSWindow?`
- `private var settingsWindow: NSWindow?`

### 2.2 applicationDidFinishLaunching

1. `NetworkMonitor.shared.start()`.
2. Подписки на `NotificationCenter`: `.showSetup` → `handleShowSetup()`,
   `.showSettings` → `handleShowSettings()`.
3. Если `!appState.hasCompletedSetup` → `showSetupWindow()`.
4. Иначе: `appState.startHotkeyMonitoring()`,
   `appState.startAccessibilityPolling()`,
   `Task { @MainActor in UpdateManager.shared.startPeriodicChecks() }`;
   и если `!AXIsProcessTrusted()` → `appState.showAccessibilityAlert()`.

### 2.3 Окно Setup

`showSetupWindow()`:

- `NSApp.setActivationPolicy(.regular)`.
- content: `SetupView(onComplete: { [weak self] in self?.completeSetup() })`
  + `.environmentObject(appState)`.
- `NSWindow(contentRect: 0,0, 520×680, styleMask: [.titled, .closable, .fullSizeContentView], backing: .buffered, defer: false)`.
- `window.title = AppName.displayName`; `titlebarAppearsTransparent = true`;
  `isMovableByWindowBackground = true`; `minSize = 520×680`;
  `isReleasedWhenClosed = false`; `center()`; `makeKeyAndOrderFront(nil)`;
  `NSApp.activate(ignoringOtherApps: true)`.

`completeSetup()` (вызывается по «Get Started» на последнем шаге):

1. `appState.hasCompletedSetup = true`.
2. `setupWindow?.close()`; `setupWindow = nil`.
3. `NSApp.setActivationPolicy(.accessory)`.
4. `startHotkeyMonitoring()`, `startAccessibilityPolling()`,
   `UpdateManager.shared.startPeriodicChecks()` (в `Task { @MainActor }`).
5. Если `!AXIsProcessTrusted()` → `showAccessibilityAlert()`.

### 2.4 Повторный запуск мастера (Re-run Setup)

`handleShowSetup()`:

- Если `setupWindow` существует и `isVisible` — только
  `makeKeyAndOrderFront(nil)` + `activate(ignoringOtherApps: true)` и выход
  (**один мастер за раз**: второй инстанс течёт по willClose-обзерверу и ломает
  bail-restore — это осознанное ограничение, зафиксировано в комментарии кода).
- Иначе: `wasCompleted = appState.hasCompletedSetup`;
  `appState.hasCompletedSetup = false`;
  `stopAccessibilityPolling()`; `stopHotkeyMonitoring()`; `showSetupWindow()`.
- Если `wasCompleted == true`: вешается
  `NotificationCenter.addObserver(forName: NSWindow.willCloseNotification)`:
  при закрытии окна, если `!appState.hasCompletedSetup` (мастер не пройдён —
  пользователь закрыл крестом) — **откат**: `hasCompletedSetup = true`,
  `startHotkeyMonitoring()`, `startAccessibilityPolling()`,
  `NSApp.setActivationPolicy(.accessory)`. Затем `setupWindow = nil`.
  `completeSetup()` выставляет `hasCompletedSetup = true` ДО `window.close()`,
  поэтому при нормальном завершении откат не срабатывает.

### 2.5 Окно Settings

`showSettingsWindow()`:

- `NSApp.setActivationPolicy(.regular)`.
- Если `settingsWindow` существует и `isVisible` — поднять на передний план
  (`makeKeyAndOrderFront` + `activate`) и выйти.
- Если `settingsWindow == nil` — `presentSettingsWindow()`, иначе просто поднять.

`presentSettingsWindow()`:

- content: `SettingsView().environmentObject(appState)` в `NSHostingView`.
- `NSWindow(contentRect: 0,0, 780×540, styleMask: [.titled, .closable, .resizable, .miniaturizable], ...)`.
- `title = AppName.displayName`; `isReleasedWhenClosed = false`; `center()`;
  `makeKeyAndOrderFront(nil)`; `activate(ignoringOtherApps: true)`.
- `willCloseNotification`: если `setupWindow == nil` →
  `NSApp.setActivationPolicy(.accessory)`; `settingsWindow = nil`.

### 2.6 Reopen

`applicationShouldHandleReopen(_:hasVisibleWindows:)`:
`guard appState.hasCompletedSetup else { return true }`;
если `!flag` (нет видимых окон — например, клик по иконке в Dock) →
`showSettingsWindow()`. Всегда возвращает `true`.

`AppName.displayName` = `CFBundleName` из Info.plist, fallback `"OmniFlow"`.

## 4. RecordingOverlay

Файл `RecordingOverlay.swift`. Оверлей — безоконный `NSPanel` у верхней кромки
экрана. Дизайн — порт вин-версии `OverlayForm.cs` (обновлено 2026-11-01): одна
тёмная карточка 480×64 вместо «крыльев нотча»/пилюли. Старые winged/pill-режимы
удалены; WaveformView сохранён только для микротеста в Setup.

### 4.1 Состояние

```swift
final class RecordingOverlayState: ObservableObject {
    @Published var phase: OverlayPhase = .recording
    @Published var audioLevel: Float = 0.0
    @Published var recordingTriggerMode: RecordingTriggerMode = .hold   // .hold | .toggle
    @Published var isCommandMode = false
    @Published var interimTranscript: String = ""   // живой текст Live-стрима
    @Published var statusText: String = ""          // "Transcribing..." / "Transcription failed" / тост ошибки
    @Published var targetAppName: String = ""       // paste-цель для пилюли "→ App"
    @Published var updateVersion: String = ""
    @Published var errorMessage: String?
    @Published var toastID: UUID?
}
enum OverlayPhase { case initializing, recording, transcribing, feedback, updateAvailable }
```

### 4.2 NSPanel — параметры

`makeOverlayPanel(targetFrame:screen:)`:

- `NSPanel(contentRect:, styleMask: [.borderless, .nonactivatingPanel], backing: .buffered, defer: false)`
- `backgroundColor = .clear`, `isOpaque = false`, `hasShadow = false`
  (тень рисует SwiftUI-карточка: `.shadow(color: .black.opacity(0.38), radius: 10, y: 4)`),
- `level = .screenSaver`
- `ignoresMouseEvents = true` (далее управляется динамически)
- `collectionBehavior = [.canJoinAllSpaces]`
- `isReleasedWhenClosed = false`, `hidesOnDeactivate = false`.

**Динамика `ignoresMouseEvents`** (`overlayAcceptsMouseEvents`):
`true` только когда `(phase == .recording && recordingTriggerMode == .toggle)`
(пилюля REC кликабельна = Stop) **или** `phase == .updateAvailable`.
Все прочие фазы — сквозной клик.

Контент — `NSHostingView` c корнем `RecordingOverlayView.frame(cardSize())`;
фон/скругление рисует сама карточка (панель прозрачна). Хостинг растягивается
(`autoresizingMask = [.width, .height]`).

Расширение `NSScreen.displayID`:
`deviceDescription[NSDeviceDescriptionKey("NSScreenNumber")] as? CGDirectDisplayID`.

### 4.3 Выбор дисплея (`targetScreen`)

Источник — `UserDefaults.standard.integer(forKey: "overlay_display_id")`:

| Значение | Поведение |
|---|---|
| `0` (дефолт) | «Active window»: `NSScreen.main ?? NSScreen.screens.first` — следует за фокусом |
| `-1` | «Primary display»: `NSScreen.screens.first ?? NSScreen.main` |
| `> 0` | Экран с `displayID == savedID`; если отключён — fallback `NSScreen.screens.first ?? NSScreen.main` |

Настройка выбирается в Settings → Recording Overlay → «Show on» (§6.2.8).

### 4.4 Геометрия карточки (паритет `OverlayForm.cs`)

Одна логическая карточка (SwiftUI points; Retina масштабирует сам):

- Обычные фазы: `480 × 64` (`cardWidth/cardHeight`).
- `.updateAvailable`: `200 × 44`.

Позиция — **верх по центру целевого экрана, 12pt под меню-баром/нотом**
(низ экрана — там поля ввода, карточка их не перекрывает):

```text
x = clamp(visibleFrame.midX − w/2, minX + 8, maxX − w − 8)
y = clamp(visibleFrame.maxY − 12 − h, minY + 8, maxY − h − 8)
```

`visibleFrame` = ниже меню-бара, поэтому на нотч-маках карточка падает сразу
под нотч. Константы карточки (= вин, @96 DPI): радиус 12, `edgePad 10`,
эквалайзер x=14, бары 4×5 с зазором 3 (32×36, min-высота 6), gap до текста 12,
пилюли h=16 зазор 4, внутренний пад пилюль 9, точка 6, текстовый блок −9pt
по вертикали.

### 4.5 Внешний вид и контент (`OverlayCard`)

- Фон: вертикальный градиент `#222229 → #141419`; скругление 12; рамка 1pt
  `#40404A` (error-режим — `#CE4636`); тень SwiftUI. Палитра — `Theme.cs`:
  `Accent` MediumSeaGreen, `AccentBright` (128,205,158), `Danger` Tomato,
  `DangerStrong` (206,70,54), `TextBright` (240,240,244), `TextCaption` (139,139,151).
- Слева — **эквалайзер**: 5 баров, градиент сверху `AccentBright@168/255` →
  снизу `Accent` (error: `DangerStrong → Danger`), скругление 2.
- Текст: primary = `interimTranscript` (если есть), иначе `statusText`
  (error: `errorMessage ?? statusText`). `.system(size: 13)`,
  `.lineLimit(2)` (две строки — как текстовый блок вин-карточки),
  `truncationMode(.head)` — новые слова видны, старое съедается слева
  (аналог вин-`FitTail`); при `isCommandMode` слева иконка `pencil`.
- Справа — колонка из двух пилюль:
  - `● REC` (error: `● ERROR`): точка 6pt `Danger` (error: `DangerStrong`),
    текст 10pt semibold `AccentBright` (error: `Danger`), фон тёмно-красный
    `RGB(120,40,44)@48/255` (error: `RGB(24,24,28)@60/255`). В toggle-режиме
    записи пилюля REC — **кнопка Stop** (`onStopButtonPressed`).
  - `→ {targetAppName}` или `→ clipboard`: текст 10pt `TextCaption`,
    фон `RGB(38,38,46)`, ellipsis по хвосту. Имя приложения прилетает из
    `AppState.startContextCapture()` → `updateTargetApp`.
- `.initializing` → карточка с `InitializingDotsView` по центру (без пилюль).
- `.updateAvailable` → `UpdateAvailableOverlayView` (кнопка «Update Available»)
  в карточке 200×44 с тем же фоном/рамкой/тенью.

**Эквалайзер (`EqualizerBarsView`)** — математика вин-`TickAnimation`,
но без таймера: `TimelineView(.animation(minimumInterval: 1/30))` (display link)
считает на кадр `wave = 0.55 + 0.45*sin(t*6.36 + phase_i)` и
`floor = 0.06 + 0.02*sin(t*2.73 + phase_i*2)`; высота =
`max(6, 36 * max(level*wave, floor))`. Плавность атаки/спада уровня даёт
`.animation(.easeOut(duration: 0.16), value: level)` на баре. Фазы фиксированные
`[0.37, 1.93, 2.87, 4.41, 5.62]` (вин — fixed seed).

### 4.6 Анимации

- **Первый показ (drop-in)**: панель ставится в «скрытый» кадр над экраном
  (`y = screen.frame.maxY`), `alphaValue = 1`, `orderFrontRegardless()`, затем
  `NSAnimationContext.runAnimationGroup`: `duration = 0.18`,
  `timingFunction = CAMediaTimingFunction(controlPoints: 0.34, 1.56, 0.64, 1.0)`
  (перелёт с лёгким overshoot).
- **Ресайз** (`resize(panel:to:animated:)`): не анимированно — `setFrame`;
  анимированно — `NSAnimationContext` `duration = 0.22`, `.easeInEaseOut`.
- Повторный показ существующей панели: обновить `ignoresMouseEvents`,
  заменить `contentView`, `resize(animated:)`, `alphaValue = 1`,
  `orderFrontRegardless()`.
- Внутри SwiftUI: `.animation(.easeInOut(duration: 0.18), value: phase)` на карточке;
  появление/исчезновение текста — transition/opacity.

### 4.7 API менеджера (`RecordingOverlayManager`)

Все методы пулятся на main через `DispatchQueue.main.async`.

| Метод | Что делает |
|---|---|
| `showInitializing(mode:isCommandMode:)` | сброс текста сессии (`resetSessionText`); фаза `.initializing`; `audioLevel = 0`; показ без ресайз-анимации |
| `showRecording(mode:isCommandMode:)` | сброс текста; фаза `.recording`, `audioLevel = 0` |
| `transitionToRecording(mode:isCommandMode:)` | фаза `.recording` + показ (инициализация→запись) |
| `setRecordingTriggerMode(_:animated:)` | смена hold/toggle + показ |
| `updateAudioLevel(_ level: Float)` | `overlayState.audioLevel = level` |
| `updateInterimTranscript(_ text: String)` | trim; кап `maxStoredTranscriptChars = 400` (хвост, префикс `"…"`); → `interimTranscript` |
| `updateTargetApp(_ appName: String)` | → `targetAppName` (пилюля назначения) |
| `showTranscribing()` | фаза `.transcribing`, `statusText = "Transcribing..."`; interim-текст сохраняется в карточке |
| `showFailureIndicator()` | фаза `.feedback` без сообщения: `statusText = "Transcription failed"` — красная карточка с `● ERROR` |
| `showError(_ message: String)` | тост ошибки, см. ниже |
| `showUpdateAvailable(version: String)` | `isCommandMode = false`; `updateVersion`; фаза `.updateAvailable` |
| `dismiss()` | → `dismissAll()` |

Колбэки, назначаемые AppState: `onStopButtonPressed` (клик по REC в toggle),
`onUpdateOverlayPressed` (клик по update-баннеру → `showUpdateAlert()`).

**Тост ошибки (`showError`)**:

- Константа `maxToastMessageLength = 90`: сообщение длиннее обрезается до
  первых 89 символов + `"…"` (полный текст остаётся в os_log).
- Генерируется `toastID = UUID()`; ставятся `errorMessage`, `toastID`,
  `statusText`; фаза `.feedback` (красная карточка); показ.
- Через `asyncAfter(deadline: .now() + 6.0)` авто-скрытие, но **только если**
  фаза всё ещё `.feedback`, `errorMessage == truncated` и `toastID` совпадает.
  По истечении: `errorMessage = nil`, `toastID = nil`, `dismissAll()`.

**dismissAll — важный нюанс**:

```text
toastHideToken = nil; isCommandMode = false; updateVersion = ""
errorMessage = nil; toastID = nil; interimTranscript = ""; statusText = ""
panel.orderOut(nil)
panel.contentView = nil   // ОБЯЗАТЕЛЬНО
panel.close()
overlayWindow = nil
```

`orderOut` сам по себе оставляет панель в `NSApp.windows` с примонтированной
иерархией SwiftUI — анимации `repeatForever` продолжают гонять Core Animation
вечно. Поэтому перед `close()` нужно **смонтировать контент** (`contentView = nil`).

### 4.8 Waveform-компоненты (только Setup)

**WaveformView** (микротест микрофона в Setup, 9 полос): `barCount = 9`,
`multipliers = [0.35, 0.55, 0.75, 0.9, 1.0, 0.9, 0.75, 0.55, 0.35]`,
`HStack(spacing: 2.5)`, `.frame(height: 24)`. Полоса `WaveformBar`: `Capsule`
белый, width 3, height `2 + (22 − 2) * amplitude`.

- При `showsActivityPulse` содержимое обёрнуто в
  `TimelineView(.animation(minimumInterval: 1/30))`.
- Амплитуда полосы `i`: `base = min(max(audioLevel,0) * multiplier[i], 1)`;
  при пульсе: `travelingWave = 0.5 + 0.5*sin(t*6.2 − i*0.78)`;
  `shimmer = 0.5 + 0.5*sin(t*3.1 + i*0.5)`; `pulse = travelingWave*0.22 + shimmer*0.06`;
  `saturationRelief = base * (0.74 + pulse)`; `quietPulse = (1 − base) * (0.04 + pulse*0.28)`;
  итог `min(saturationRelief + quietPulse, 1)`.
- Анимация полосы: `.spring(response: 0.18 + normalizedDistance*0.06, dampingFraction: 0.88)`
