## 1. Точка входа приложения (App.swift)

`@main struct OmniFlowApp: App` с `@NSApplicationDelegateAdaptor(AppDelegate.self)`.

Единственная сцена — `MenuBarExtra(isInserted: $showMenuBarIcon)`:

- content: `MenuBarView().environmentObject(appDelegate.appState)`
- label: `MenuBarLabel().environmentObject(appDelegate.appState)`
- `showMenuBarIcon` — `@AppStorage("show_menu_bar_icon")`, дефолт `true`
  (переключается из Settings → General → App → «Show menu bar icon»).

### MenuBarLabel (иконка в статус-баре)

Логика выбора иконки (`private var iconName`):

| Состояние appState | SF Symbol |
|---|---|
| `isRecording == true` | `record.circle` |
| `isTranscribing == true` (и не recording) | `ellipsis.circle` |
| иначе (idle) | `waveform` |

- `@ObservedObject var notificationManager = VocabularyNotificationManager.shared`;
  если `notificationManager.showCheckmark == true` — слева дополнительно
  рисуется `Image(systemName: "checkmark")` (вспышка подтверждения после
  «Paste Custom Word», см. §3.15). Анимация появления/исчезания checkmark:
  `.animation(.easeInOut(duration: 0.2), value: notificationManager.showCheckmark)`.
  `showCheckmark` держится ровно 2 секунды (см. §9.4).
- **Dev-бандл:** если `AppBuild.isDevBundle && !isRecording && !isTranscribing`,
  вместо SF Symbol рисуется штампованная иконка
  `StampedMenuBarIcon.templateImage` с `renderingMode(.template)`.
  `AppBuild.isDevBundle == (Bundle.main CFBundleName == "OmniFlow Dev")`.

### StampedMenuBarIcon (рисование в коде, не ассет)

`NSImage` размера `NSSize(width: 18, height: 16)`, `flipped: false`, `isTemplate = true`.
Путь с `windingRule = .evenOdd`: скруглённый прямоугольник на весь rect
(xRadius 3, yRadius 3) минус 5 вертикальных «столбиков»-эквалайзера
(каждый — rounded rect, xRadius/yRadius 0.75, ширина 1.5):

| x | y | height |
|------|-----|--------|
| 3.0 | 7.0 | 2.0 |
| 5.5 | 5.0 | 6.0 |
| 8.0 | 3.0 | 10.0 |
| 10.5 | 4.0 | 8.0 |
| 13.0 | 6.0 | 4.0 |

Заливка `NSColor.black`. Т.е. иконка «волна в скруглённой плашке», template —
меню-бар сам красит в чёрный/белый.

## 2. AppDelegate: окна и activation policy

### 2.1 Свойства

- `let appState = AppState()`
- `var setupWindow: NSWindow?`
- `private var settingsWindow: NSWindow?`

### 2.2 applicationDidFinishLaunching

1. `NetworkMonitor.shared.start()`.
2. Подписки на `NotificationCenter`: `.showSetup` → `handleShowSetup()`,
   `.showSettings` → `handleShowSettings()`.
3. Если `!appState.hasCompletedSetup` → `showSetupWindow()`.
4. Иначе: `appState.startHotkeyMonitoring()`,
   `appState.startAccessibilityPolling()`,
   `Task { @MainActor in UpdateManager.shared.startPeriodicChecks() }`;
   и если `!AXIsProcessTrusted()` → `appState.showAccessibilityAlert()`.

### 2.3 Окно Setup

`showSetupWindow()`:

- `NSApp.setActivationPolicy(.regular)`.
- content: `SetupView(onComplete: { [weak self] in self?.completeSetup() })`
  + `.environmentObject(appState)`.
- `NSWindow(contentRect: 0,0, 520×680, styleMask: [.titled, .closable, .fullSizeContentView], backing: .buffered, defer: false)`.
- `window.title = AppName.displayName`; `titlebarAppearsTransparent = true`;
  `isMovableByWindowBackground = true`; `minSize = 520×680`;
  `isReleasedWhenClosed = false`; `center()`; `makeKeyAndOrderFront(nil)`;
  `NSApp.activate(ignoringOtherApps: true)`.

`completeSetup()` (вызывается по «Get Started» на последнем шаге):

1. `appState.hasCompletedSetup = true`.
2. `setupWindow?.close()`; `setupWindow = nil`.
3. `NSApp.setActivationPolicy(.accessory)`.
4. `startHotkeyMonitoring()`, `startAccessibilityPolling()`,
   `UpdateManager.shared.startPeriodicChecks()` (в `Task { @MainActor }`).
5. Если `!AXIsProcessTrusted()` → `showAccessibilityAlert()`.

### 2.4 Повторный запуск мастера (Re-run Setup)

`handleShowSetup()`:

- Если `setupWindow` существует и `isVisible` — только
  `makeKeyAndOrderFront(nil)` + `activate(ignoringOtherApps: true)` и выход
  (**один мастер за раз**: второй инстанс течёт по willClose-обзерверу и ломает
  bail-restore — это осознанное ограничение, зафиксировано в комментарии кода).
- Иначе: `wasCompleted = appState.hasCompletedSetup`;
  `appState.hasCompletedSetup = false`;
  `stopAccessibilityPolling()`; `stopHotkeyMonitoring()`; `showSetupWindow()`.
- Если `wasCompleted == true`: вешается
  `NotificationCenter.addObserver(forName: NSWindow.willCloseNotification)`:
  при закрытии окна, если `!appState.hasCompletedSetup` (мастер не пройдён —
  пользователь закрыл крестом) — **откат**: `hasCompletedSetup = true`,
  `startHotkeyMonitoring()`, `startAccessibilityPolling()`,
  `NSApp.setActivationPolicy(.accessory)`. Затем `setupWindow = nil`.
  `completeSetup()` выставляет `hasCompletedSetup = true` ДО `window.close()`,
  поэтому при нормальном завершении откат не срабатывает.

### 2.5 Окно Settings

`showSettingsWindow()`:

- `NSApp.setActivationPolicy(.regular)`.
- Если `settingsWindow` существует и `isVisible` — поднять на передний план
  (`makeKeyAndOrderFront` + `activate`) и выйти.
- Если `settingsWindow == nil` — `presentSettingsWindow()`, иначе просто поднять.

`presentSettingsWindow()`:

- content: `SettingsView().environmentObject(appState)` в `NSHostingView`.
- `NSWindow(contentRect: 0,0, 780×540, styleMask: [.titled, .closable, .resizable, .miniaturizable], ...)`.
- `title = AppName.displayName`; `isReleasedWhenClosed = false`; `center()`;
  `makeKeyAndOrderFront(nil)`; `activate(ignoringOtherApps: true)`.
- `willCloseNotification`: если `setupWindow == nil` →
  `NSApp.setActivationPolicy(.accessory)`; `settingsWindow = nil`.

### 2.6 Reopen

`applicationShouldHandleReopen(_:hasVisibleWindows:)`:
`guard appState.hasCompletedSetup else { return true }`;
если `!flag` (нет видимых окон — например, клик по иконке в Dock) →
`showSettingsWindow()`. Всегда возвращает `true`.

`AppName.displayName` = `CFBundleName` из Info.plist, fallback `"OmniFlow"`.

## 3. MenuBarView (меню статус-бара)

Корень: `VStack(spacing: 4)` + `.padding(4)`. Все элементы в порядке ниже.
`@ObservedObject private var updateManager = UpdateManager.shared`.

Вспомогательные функции:

- `appVersion` = `CFBundleShortVersionString`, fallback `"1.0"`.
- `transcriptText(for:)` — postProcessedTranscript, а если после trim пусто — rawTranscript (оба trim от whitespacesAndNewlines).
- `transcriptFull(for:)` — без trim (полный текст для копирования).
- `transcriptSnippet(for:)` — перевести `\n` в пробел, trim; если пусто → `"(no transcript)"`; если `count > 48` → `prefix(48) + "..."`.
- `recentHistoryItems` = `appState.pipelineHistory.filter { !transcriptText($0).isEmpty }.prefix(10)`.

### Структура меню — по пунктам сверху вниз

1. **Заголовок**: `Text("\(AppName.displayName) v\(appVersion)")`,
   `.font(.caption)`, `.foregroundStyle(.secondary)`, padding h16/v4. Затем `Divider()`.

2. **Баннер Screen Recording** (если `!appState.hasScreenRecordingPermission`):
   Button `.plain`, `Label("Screen Recording Permission Needed", systemImage: "camera.viewfinder")`,
   белый текст, `.font(.caption.weight(.semibold))`, padding h16/v8,
   `frame(maxWidth: .infinity)`, фон `Color.orange`. Действие —
   `appState.requestScreenCapturePermission()`. Затем `Divider()`.

3. **Баннер Accessibility** (если `!appState.hasAccessibility`):
   `Label("Accessibility Required", systemImage: "exclamationmark.triangle.fill")`,
   стиль как выше, но фон `Color.red`. Действие —
   `appState.showAccessibilityAlert()`. Затем `Divider()`.

4. **Статусная строка**:
   - recording: `Label("Recording...", systemImage: "record.circle")`, `.foregroundStyle(.red)`, padding h16/v6;
   - transcribing: `Label(appState.debugStatusMessage, systemImage: "ellipsis.circle")`, `.secondary`;
   - иначе: `Text(appState.shortcutStatusText)` `.secondary .caption` —
     текст вида «Hold X or tap Y to dictate» / «Hold X to dictate» /
     «Tap Y to dictate» / «No dictation shortcut enabled» /
     «Global shortcuts unavailable» (при ошибке мониторинга хоткеев).
   Затем `Divider()`.

5. **Старт/стоп**: `Button(appState.isRecording ? "Stop Recording" : "Start Dictating") { appState.toggleRecording() }`,
   `.disabled(appState.isTranscribing)`.

6. **Ошибки** (каждая опционально, с `Divider()` перед собой):
   - `appState.hotkeyMonitoringErrorMessage` — красный `.caption`, padding h16, `lineLimit(3)`.
   - `appState.errorMessage` — так же.

7. `Divider()`.

8. **Paste Again** (если `!appState.lastTranscript.isEmpty && !isRecording && !isTranscribing`):
   - Button с заголовком: shortcut disabled → `"Paste Again"`, иначе
     `"Paste Again  (\(appState.copyAgainShortcut.displayName))"` (два пробела перед скобкой).
     Действие — `appState.copyLastTranscriptToPasteboard()`.
   - **Превью**: обрезка до 35 символов —

     выводится `Text("\u{201C}\(truncated)\u{201D}")` (типографские кавычки “…”) `.caption .secondary`,
     padding h16, `lineLimit(4)`, `frame(maxWidth: 280, alignment: .leading)`.

9. **Menu("History")**:
   - пусто → `Text("No transcripts yet")`;
   - иначе `ForEach(recentHistoryItems)` (макс. 10, новейшие первыми — порядок
     `pipelineHistory`): Button c label `transcriptSnippet` (48 симв. + `...`),
     действие — копирование `transcriptFull` в `NSPasteboard.general`

     После списка `Divider()`.
   - `Button("Open Run Log")` → `appState.selectedSettingsTab = .runLog` и

11. **Paste Custom Word to Vocabulary**: Button →
    `if appState.pasteWordToVocabulary() != nil { VocabularyNotificationManager.shared.flashCheckmark() }`

    checkmark в статус-баре, §9.4).

12. `Divider()`.

13. **Подменю шорткатов** — три одинаковых по шаблону `Menu`:

## 4. RecordingOverlay

Файл `RecordingOverlay.swift`. Оверлей — безоконный `NSPanel` у верхней кромки
экрана; два layout-режима: «winged» (крылья вокруг выреза нотча) и «pill»
(классическая пилюля/плашка).

### 4.1 Состояние

```swift
final class RecordingOverlayState: ObservableObject {
    @Published var phase: OverlayPhase = .recording
    @Published var audioLevel: Float = 0.0
    @Published var recordingTriggerMode: RecordingTriggerMode = .hold   // .hold | .toggle
    @Published var isCommandMode = false
    @Published var updateVersion: String = ""
    @Published var errorMessage: String?
    @Published var toastID: UUID?
}
enum OverlayPhase { case initializing, recording, transcribing, feedback, updateAvailable }
```

### 4.2 NSPanel — параметры

`makeOverlayPanel(width:height:)`:

- `NSPanel(contentRect:, styleMask: [.borderless, .nonactivatingPanel], backing: .buffered, defer: false)`
- `backgroundColor = .clear`, `isOpaque = false`, `hasShadow = true`
  (но менеджер при первом показе переопределяет в `false` — см. §4.7),
- `level = .screenSaver`
- `ignoresMouseEvents = true` (далее управляется динамически)
- `collectionBehavior = [.canJoinAllSpaces]`
- `isReleasedWhenClosed = false`, `hidesOnDeactivate = false`.

**Динамика `ignoresMouseEvents`** (`overlayAcceptsMouseEvents`):
`true` только когда `(phase == .recording && recordingTriggerMode == .toggle)`
(кнопка Stop кликабельна) **или** `phase == .updateAvailable` (баннер кликабельный).
Все прочие фазы — сквозной клик.

Контент — `NSHostingView` c корнем
`rootView.frame(width:height:).background(Color.black).clipShape(UnevenRoundedRectangle(bottomLeadingRadius: r, bottomTrailingRadius: r))`
(`makeNotchContent`). Хостинг растягивается (`autoresizingMask = [.width, .height]`).

Расширение `NSScreen.displayID`:
`deviceDescription[NSDeviceDescriptionKey("NSScreenNumber")] as? CGDirectDisplayID`.

### 4.3 Выбор дисплея (`targetScreen`)

Источник — `UserDefaults.standard.integer(forKey: "overlay_display_id")`:

| Значение | Поведение |
|---|---|
| `0` (дефолт) | «Active window»: `NSScreen.main ?? NSScreen.screens.first` — следует за фокусом |
| `-1` | «Primary display»: `NSScreen.screens.first ?? NSScreen.main` |
| `> 0` | Экран с `displayID == savedID`; если отключён — fallback `NSScreen.screens.first ?? NSScreen.main` |

Настройка выбирается в Settings → Recording Overlay → «Show on» (§6.2.8).

### 4.4 Геометрия

- `screenHasNotch` = `targetScreen.safeAreaInsets.top > 0`.
- `notchWidth` = `screen.frame.width - auxiliaryTopLeftArea.width - auxiliaryTopRightArea.width`
  (0, если нет нотча или auxiliary-области nil).
- `notchOverlap` = `screen.frame.maxY - screen.visibleFrame.maxY`
  (высота перекрытия меню-баром; на безнотчевых экранах равна высоте меню-бара).

**useWingedLayout** (крылья) — true только если `screenHasNotch` **и**
`use_compact_overlay` (UserDefaults bool, дефолт `true`), и фаза:
- `.recording`, `.initializing`, `.transcribing` → true;
- `.feedback` → true только если `errorMessage` nil/пустая (голый X);
- `.updateAvailable` → false (всегда drop-down pill).

**Размеры крыльев**: `wingWidth = 36`; `leftWingWidth = rightWingWidth = 36`.

`overlayFrame`:
- Winged: `panelWidth = 36 + notchWidth + 36`, `panelHeight = notchOverlap`,
  `panelX = (auxiliaryTopLeftArea?.maxX ?? midX - notchWidth/2) - 36`,
  `panelY = screen.frame.maxY - panelHeight` (панель целиком внутри меню-бара).
- Pill: `height = (use_compact_overlay && !forceDropDownPill) ? notchOverlap : 38 + (screenHasNotch ? notchOverlap : 0)`;
  `forceDropDownPill = (phase == .feedback && errorMessage не пустая)` — тосты
  ошибки всегда показываются в высокой пилюле для читаемости.
  `x = screen.frame.midX - width/2`, `y = screen.frame.maxY - height`.

`overlayWidth` (только pill-режим):
- `.transcribing` с зафиксированной `lockedOverlayWidth` → ширина зафиксирована
  (ставится в `setTranscribingPhase` = ширина панели на момент перехода, чтобы
  пилюля не прыгала).
- `.feedback`: если message пуст/nil → `92`; иначе
  `min(420, max(180, CGFloat(msg.count) * 6.8 + 60))` — ~6.8pt/символ + 60pt хром;
  при нотче `max(notchWidth, feedbackWidth)`.
- `.updateAvailable`: `190` (при нотче `max(notchWidth, 190)`).
- Базовые: command mode → `180`; `.recording && triggerMode == .toggle` → `150`;
  иначе (hold) → `92`. При нотче `max(notchWidth, base)`.

### 4.5 Анимации

- **Первый показ (drop-down)**: панель ставится в «скрытый» кадр
  `NSRect(x: frame.x, y: screen.frame.maxY, width:, height:)` (над экраном),
  `alphaValue = 1`, `orderFrontRegardless()`, затем
  `NSAnimationContext.runAnimationGroup`: `duration = 0.18`,
  `timingFunction = CAMediaTimingFunction(controlPoints: 0.34, 1.56, 0.64, 1.0)`
  (перелёт с лёгким overshoot), `panel.animator().setFrame(frame)`.
  При первом создании `panel.hasShadow = false`.
- **Ресайз** (`resize(panel:to:animated:)`): не анимированно — `setFrame`;
  анимированно — `NSAnimationContext` `duration = 0.22`, timing
  `.easeInEaseOut`.
- Повторный показ существующей панели (все фазы кроме первой): обновить
  `ignoresMouseEvents`, заменить `contentView`, `resize(animated:)`,
  `alphaValue = 1`, `orderFrontRegardless()`.
- Внутри SwiftUI-контента переходы контента — `.transition(.opacity)` и
  `.transition(.move(edge: .trailing).combined(with: .opacity))` (кнопка Stop),
  групповые `.animation(.spring(response: 0.28, dampingFraction: 1.0), value:)`
  на `phase`, `recordingTriggerMode`, `isCommandMode` (и в winged — на `phase`).

### 4.6 API менеджера (`RecordingOverlayManager`)

Все методы пулятся на main через `DispatchQueue.main.async`.

| Метод | Что делает |
|---|---|
| `showInitializing(mode:isCommandMode:)` | `lockedOverlayWidth = nil`; фаза `.initializing`; `audioLevel = 0`; показ без ресайз-анимации (`animatedResize: false`) |
| `showRecording(mode:isCommandMode:)` | фаза `.recording`, `audioLevel = 0`, показ с анимацией ресайза |
| `transitionToRecording(mode:isCommandMode:)` | фаза `.recording` + `updateOverlayLayout(animated: true)` (панель уже видна — инициализация→запись) |
| `setRecordingTriggerMode(_:animated:)` | смена hold/toggle + перелайаут |
| `updateAudioLevel(_ level: Float)` | просто `overlayState.audioLevel = level` |
| `showTranscribing()` | `setTranscribingPhase()`: зафиксировать ширину (`lockedOverlayWidth = overlayWindow?.frame.width ?? overlayWidth`), фаза `.transcribing`, показ с анимацией |
| `showFailureIndicator()` | `lockedOverlayWidth = nil`, фаза `.feedback` без сообщения (голый X) |
| `showError(_ message: String)` | тост ошибки, см. ниже |
| `showUpdateAvailable(version: String)` | `lockedOverlayWidth = nil`; `isCommandMode = false`; `updateVersion = version`; фаза `.updateAvailable`, показ с анимацией |
| `dismiss()` | → `dismissAll()` |

Колбэки, назначаемые AppState: `onStopButtonPressed` (клик по Stop в toggle),
`onUpdateOverlayPressed` (клик по update-баннеру → `showUpdateAlert()`).

**Тост ошибки (`showError`)**:

- Константа `maxToastMessageLength = 90`: сообщение длиннее обрезается до
  первых 89 символов + `"…"` (полный текст остаётся в os_log).
- Генерируется `toastID = UUID()`; ставятся `errorMessage`, `toastID`;
  `lockedOverlayWidth = nil`; фаза `.feedback`; показ с ресайзом.
- Через `asyncAfter(deadline: .now() + 6.0)` авто-скрытие, но **только если**
  фаза всё ещё `.feedback`, `errorMessage == truncated` и `toastID` совпадает
  (иначе тост уже заменён новым — не трогаем). По истечении: `errorMessage = nil`,
  `toastID = nil`, `dismissAll()`.

**dismissAll — важный нюанс**:

```text
lockedOverlayWidth = nil; isCommandMode = false; updateVersion = ""
panel.orderOut(nil)
panel.contentView = nil   // ОБЯЗАТЕЛЬНО
panel.close()
overlayWindow = nil
```

`orderOut` сам по себе оставляет панель в `NSApp.windows` с примонтированной
иерархией SwiftUI — анимации `repeatForever` (спиннеры) продолжают гонять Core
Animation вечно. Поэтому перед `close()` нужно **смонтировать контент** (`contentView = nil`).

### 4.8 Waveform-компоненты

**WaveformView** (pill, 9 полос): `barCount = 9`,
`multipliers = [0.35, 0.55, 0.75, 0.9, 1.0, 0.9, 0.75, 0.55, 0.35]`,
`HStack(spacing: 2.5)`, `.frame(height: 24)`. Полоса `WaveformBar`: `Capsule`
белый, width 3, height `2 + (22 − 2) * amplitude` (min 2, max 22).

- При `showsActivityPulse` содержимое обёрнуто в
  `TimelineView(.animation(minimumInterval: 1/30))` — 30 fps.
- Амплитуда полосы `i`: `base = min(max(audioLevel,0) * multiplier[i], 1)`;
  при пульсе: `travelingWave = 0.5 + 0.5*sin(t*6.2 − i*0.78)`;
  `shimmer = 0.5 + 0.5*sin(t*3.1 + i*0.5)`; `pulse = travelingWave*0.22 + shimmer*0.06`;
  `saturationRelief = base * (0.74 + pulse)`; `quietPulse = (1 − base) * (0.04 + pulse*0.28)`;
  итог `min(saturationRelief + quietPulse, 1)` (тихая запись — полосы дышат).
- Анимация полосы: `.spring(response: 0.18 + normalizedDistance*0.06, dampingFraction: 0.88)`
  c `delay = distanceFromCenter * 0.01` (центр отвечает быстрее), value `audioLevel`;
  `centerIndex = (9−1)/2 = 4`.

**CompactWaveformView** (крыло, 5 полос): `barCount = 5`,
`multipliers = [0.5, 0.75, 1.0, 0.75, 0.5]`, spacing 1.5, height 18; полоса:
width 2, min 2, max 14; spring `response: 0.18, dampingFraction: 0.88` без
индивидуальных задержек; пульс-математика та же (формулы идентичны).

**ProcessingIndicatorView** (pill transcribing): первые **1 секунда** —
`ProcessingWaveformView`: 5 «пилюль» (`Capsule`, width 4, min 4 / max 18,
spacing 4, height 20), TimelineView 1/30:
`phase(i) = ((t − i*0.11) mod 1.05) / 1.05`; `wave = 0.5 + 0.5*sin(phase*2π − π/2)`;
`pulse = pow(wave, 1.9)`; `amplitude = min(0.18 + (1 − centerDist)*0.1 + pulse*0.68, 1)`;
`opacity = 0.42 + pulse*0.52` (`centerDist = |i − 2| / 2`).
Через `Task.sleep(1_000_000_000)` (1 c) — переключение в **спиннер** с
`.easeInOut(duration: 0.18)`: `Circle().trim(from: 0.1, to: 0.9)`, белый,
`StrokeStyle(lineWidth: 2.5, lineCap: .round)`, кадр 16×16, вращение
`withAnimation(.linear(duration: 0.8).repeatForever(autoreverses: false))` 0→360°.

**CompactProcessingIndicatorView** — то же, но спиннер 12×12, lineWidth 2.0,
пилюли width 2, min 2 / max 12, spacing 2, height 18.

**InitializingDotsView**: 3 круга 4.5×4.5, spacing 4; активный — белый
`opacity(0.9)`, остальные `opacity(0.25)`; `Timer.scheduledTimer(withTimeInterval: 0.5, repeats: true)`
циклит `activeDot = (activeDot + 1) % 3`; `.animation(.easeInOut(duration: 0.4))`;
таймер инвалидируется в `onDisappear`.

  активный `opacity(1.0)` + `scaleEffect(1.3)`, таймер `Timer.publish(every: 0.4)`,
  анимация 0.3 c) + «Transcribing...».
- **done**: зелёная `checkmark.circle.fill` 60pt и три варианта: ошибка —
  «Something went wrong» + текст ошибки; пустой транскрипт — «No speech
  detected»; успех — «Perfect — \(AppName.displayName) is ready to go.» +
  транскрипт в карточке (transition `.move(edge: .bottom)+opacity`). Во всех —
  `retryShortcutPrompt` = `"\(testShortcutPrompt) to try again"`.

Механика: используется **отдельный** `SetupTestHotkeyHarness` (свой
`HotkeyManager` + `DictationShortcutSessionController`, конфигурация только
hold+toggle, `startDelay = appState.shortcutStartDelay`; action `.start` с
отложкой через Task-sleep, `.switchedToToggle` перепланирует старт как toggle):

- `.start`: разрешён из `idle`/`done` (из done — `resetTest()`); создаётся
  `AudioRecorder`, `try recorder.startRecording(deviceUID: selectedMicrophoneID)`;
  подписка `recorder.$audioLevel` (main) → `testAudioLevel`; фаза recording
  (spring `response: 0.4, dampingFraction: 0.8`). Ошибки старта/записи →
  `testError = localizedDescription`, фаза done.
- `.stop` (только из recording): уровень в 0; `isTranscribing = true` харнесса;
  фаза transcribing; `recorder.stopRecording { url }` → при nil URL — ошибка
  «No audio file was created.»; иначе `appState.makeTranscriptionService()` и
  `service.transcribe(fileURL:)` → `testTranscript` (done) либо `testError`
  (done). После — `recorder.cleanup()`.
- `Skip`/`Continue`/`onDisappear`: `testHotkeyHarness.stop()`, отмена подписки
  уровня, отмена активной записи (`cancelRecording`).

{id, login, avatar_url, html_url}` c `avatarThumbnailUrl` (добавление `s=44`),
