# ADR-0002: Live-first и адаптивный финиш

- Статус: accepted (2026-11-01)
- Контекст: `gemini-3.5-transcribe-live` не присылает `turnComplete` на тишине,
  interim и final живут в разных полях и оба ЗАМЕНЯЮТ открытый сегмент; наивное
  ожидание события вешало спиннер на пустой записи.

## Решение

1. Выбранный пользователем канал включается сразу (live-first), отключение
   канала — только явно.
2. Финиш — адаптивный (паритет с Windows): minWait 0.8 c после streamEnd,
   settle 1.0 c тишины interim, cap 6.0 c, поллинг 0.08 c.
3. `LiveTranscriptAccumulator`: interim и final заменяют сегмент (не дописывают),
   pre-setup аудио буферизуется (drop-oldest, 200 чанков) и сливается после
   setupComplete.
4. `turnComplete` закрывает только серверный TURN, не сессию; сокет закрывается
   только по нашему streamEnd.

## Последствия

- Пустой live-результат не считается ошибкой → fallback на батч-транскрипцию.
- Быстрая вставка (десятки мс после тишины) вместо фиксированного ожидания.
