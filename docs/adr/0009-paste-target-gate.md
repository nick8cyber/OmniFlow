# ADR-0009: Верификация цели вставки перед Ctrl+V / Cmd+V

- Статус: accepted (2026-11-08)
- Контекст: аудит 2026-11-08 (полный архитектурный + логи + история) показал,
  что вставка — единственное деструктивное действие аппа — выполнялась вслепую:
  синтетический Cmd+V/Ctrl+V стрелял через 5–45 с после захвата выделения без
  единой перепроверки. В окно конвертации (транскрипция до 20 с + Live-финиш
  до 6 с + LLM до 20 с) пользователь успевает кликать и выделять — вставка
  съедала его свежее выделение, каретка перерисовывалась у якоря выделения
  («каретка прыгает, стирает лишнее»). Дополнительно: упавший Edit-трансформ
  возвращал СТАРОЕ захваченное выделение, которое вставлялось поверх текущего;
  цель не проверялась вообще (фокус мог уйти в другое окно/приложение).

## Решение

Гейт `PasteGate` (чистая логика, тестируемая без сессии; Swift `Sources/PasteGate.swift`,
C# `windows/src/FreeFlow/Core/PasteGate.cs`) вычисляется НЕПОСРЕДСТВЕННО перед
нажатием клавиш:

1. **Edit-сессии** (трансформ выделения): перечитать текущее выделение цели
   (mac: AX `kAXSelectedTextAttribute` фронтового элемента, `pasteTimeProbe()`;
   win: UIA `SelectionCapture.GetSelectedText()` после RestoreFocusToTarget).
   Не совпало (нормализация — схлопывание whitespace) или нечитаемо → **вставка
   отменяется**, транскрипт остаётся на буфере для ручной вставки, юзеру —
   внятная ошибка с причиной.
2. **Обычная диктовка**: сверяется процесс фронтового окна с процессом цели,
   захваченным на старте сессии (mac: bundle id через NSWorkspace; win: имя
   процесса по GetWindowThreadProcessId). Разъехались → отмена вставки. Неизвестные
   имена (процесс умер, доступ запрещён) считаются «непроверяемо» → вставка идёт.
3. **Упавший Edit-трансформ больше не вставляет ничего** (раньше — stale
   выделение): ошибка + текст в истории.
4. **Enter-only путь** («нажми энтер») проходит тот же гейт фокуса.
5. На скипе буфер НЕ восстанавливается — транскрипт ждёт ручного Cmd+V/Ctrl+V.

Сопутствующее (тот же проход): логирование paste-цепочки (mac: os_log категория
`Paste` — гейт-решение, факты Cmd+V/Return, исход рестора буфера; lengths и
bundle id, БЕЗ текста транскрипта; win: Debug.WriteLine + StatusChanged/ErrorOccurred);
«press enter» по умолчанию ВЫКЛ (был вкл — случайные Enter в документах/чатах);
хвостовой пробел после `.!?` — настройка (по умолчанию вкн, поведение прежнее);
Paste Again не срабатывает в живой сессии (mac — новый гард; win — IsBusy-гард
уже стоял, проверено).

## Последствия и откат

- Ложные блокировки возможны только у Edit-сессий при экзотических редакторах,
  отдающих мусорное выделение при перечитывании, — цена противоестественна
  («недовставил» вместо «стёр»). Обычная диктовка блокируется только при смене
  фокуса, что и раньше вело к вставке не туда.
- Rollback: изменения в одном коммите на репо — `git revert <commit>` возвращает
  прежнее слепое поведение целиком (ADR сознательно самодостаточен для отката).
- Не покрыто: RetryLastRecording (явное действие юзера из трея, фокус
  восстанавливается) — гейт не применён сознательно; History-retry на маке
  пишет только буфер.
